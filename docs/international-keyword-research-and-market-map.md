## Positioning

## Regional spelling strategy

Use the spelling that reads naturally in each page. Do not place both variants in every heading.

- US-style: personalized, customize, favorite.
- UK / Irish / Australian / New Zealand style: personalised, customise, favourite.
- Neutral terms that work broadly: personal, digital, online, website, webpage, template, message, invitation, shareable link.

Use one primary keyword per page. Add a small number of close variants only where the wording helps the reader. Keep US/UK spellings in the body copy naturally where useful, not as keyword lists.

## Country and language implementation rules

1. Keep the current English global version available at stable URLs.
2. Do not generate 195 near-identical `/country/` pages that simply swap a country name. Google describes pages that funnel users to one destination as doorway abuse; mass-produced, unhelpful pages can also be scaled-content abuse.
3. Do not add `hreflang` tags for country versions that do not exist. When real translated or substantially localized versions are created, give each version a distinct URL and add reciprocal `hreflang` annotations including itself and the other equivalents. Use valid language-region codes such as `en-US`, `en-GB`, `en-AU`, `en-CA`, `hi-IN`, `es-ES`, `pt-BR`, `fr-FR` only when the corresponding localized page exists.
4. Do not redirect visitors automatically based only on IP address. Offer a visible language or region choice when more versions are available.
5. Keep each market page genuinely useful: local terminology, examples, dates/time zones, language, event conventions and relevant product availability must be accurate before publishing it.
6. The app and checkout are on wishly.bd. Do not promise local-currency pricing, payment methods, product features or availability in a country unless the main product confirms them.
7. Use Search Console performance by country to decide which country/language deserves a localized version. Do not guess search volume.

## Technical state in this project

- Public canonical host: `https://wishly.rafahim.com`.
- Product host: `https://wishly.bd`.
- The HTML document language is `en` because all editorial page content is English.
- Each indexable route has a self-referencing canonical.
- `robots.txt` allows public crawling and points to `sitemap.xml`.
- Sitemap includes core pages, occasion collections, template detail pages, Insights articles and image URLs.
- `WebSite`, `Organization`, `CollectionPage`, `BlogPosting`, `AboutPage`, `HowTo`, `BreadcrumbList` and FAQ structured data are used only where relevant to visible page content.
- No country-specific `hreflang` is emitted yet because no separate translated/regional URL variants currently exist.
- Google Search does not use the `meta keywords` tag as a ranking signal. Keyword research is reflected in visible page titles, headings, copy, image alt text and internal links; the mapping is retained in project documentation for editors.
